# Hardening Plan

### A. Goal
Make VaultProxy safe to run in production AND very simple to use. Simplicity is a hard requirement.

### B. Simplicity rules
S1 A new user gets a working protected proxy in 3 steps: install, run, change base_url. No config file required.
S2 Convention over configuration. The total number of NEW settings in the whole hardening effort is at most 8; 3 are used so far (VAULT_PROFILE, MASK_SCOPE, NON_TEXT_POLICY), so at most 5 more. Each new setting needs a one-line justification. Existing settings keep names and defaults.
S3 No new abstractions: no plugin systems, store interfaces, dependency injection or user-supplied regex engine.
S4 No new runtime dependencies unless essential; optional features go in extras.
S5 Errors say what happened, why and how to fix it. No stack traces to clients, and never input text in an error.
S6 Delete before you add. Report net lines per phase and justify any phase over 400 added lines.
S7 Two profiles only: development (current behaviour) and production (refuses unsafe configuration).
If a requirement would make the tool harder to use, STOP and ask me a short question.

### C. Core contract (must stay true)
C1 Typed tokens [TYPE_N]; the same value gets the same token within a request; the vault is per-request, in memory only, never persisted.
C2 Fail closed: an unexpected masking error returns 503 and forwards nothing; STRICT_MODE plus an SLM failure returns 503.
C3 X-Vault-Report keeps its fields (additive changes only; counts only, never values).
C4 Streaming restore never leaks partial tokens (split-at-every-position tests keep passing).
C5 Everything works with GEMMA_BACKEND=off and offline.
C6 Existing env var names and development-profile defaults are unchanged.
C7 Existing tests pass, except tests that froze a "KNOWN LEAK" and are deliberately updated (list each by name).

### D. Honesty rules
Docs, UI and README must be true and measured. Never write "guarantees", "zero-trust", "100% safe", "ensures compliance"; say it reduces risk. Compliance notes: supports safeguards, not legal advice. Compare with other tools only using facts verified from their official docs in this session. Never print or log raw prompts, replies, detected values or secrets. Fake data only. Never push to a remote.

### E. Report format (end of every phase)
(1) What a user can now do, in 3 lines. (2) Commands for me to try it, including real proxy runs, not only filtered pytest. (3) Tests and the real coverage table (run pytest --cov=vaultproxy --cov-report=term-missing without disabling addopts). (4) Regression report: golden tests unchanged yes/no, and each deliberately changed test with a reason. (5) Net lines of code, and any new settings with justification. (6) Risks. Then update docs/PROGRESS.md, commit, and STOP and wait for "next".

### H. Real-use gates
The project is now intended for real-world use with real personal data and credentials. Security, fail-closed safety, and technical honesty outrank demo polish or decorative UI features. Hackathon-only and demo-only items (e.g. unauthenticated demo console endpoints, fake source badges, hardcoded fallbacks) are removed or strictly gated behind explicit development flags.

### C. Verified bugs (from an external review; each was reproduced against running servers)
B1 Gzip: when the upstream sends Content-Encoding: gzip, the proxy forwards the decoded body but keeps the content-encoding header, so clients fail (httpx DecodingError "incorrect header check"; OpenAI SDK APIConnectionError). Fix: drop content-encoding, content-length and transfer-encoding from forwarded responses (stream and non-stream). Test with an upstream that gzip-compresses.
B2 Streams kill each other: process_sse_stream calls client.aclose() on the SHARED httpx client in its finally block. Repro: a slow stream (8 content events over 4 s) plus a fast stream started 1 s later; the slow stream died at the instant the fast one ended, after 4 events, with an error event "ReadError". Fix: never close the shared client in the generator; close only that upstream response. Test: 3+ concurrent streams of different durations all complete with all events and [DONE]; a client disconnect cancels only its own upstream response.
B3 Base URL: the code appends "/v1/chat/completions" (also /v1/embeddings and /v1/models) to UPSTREAM_BASE_URL; a base URL ending in /v1 produced a 404 (path /v1/v1/...). Fix: treat UPSTREAM_BASE_URL like the OpenAI SDK's base_url: append only /chat/completions, /embeddings, /models. For backward compatibility, if the URL has no path at all, add /v1. Unit-test the URL builder for: https://api.openai.com, https://api.openai.com/v1, http://localhost:11434/v1, https://host/v1beta/openai, trailing slashes, and a path with a prefix.
B4 The concurrency limit ignores streams: the semaphore is released when the handler returns the StreamingResponse. Repro: MAX_CONCURRENT_REQUESTS=1, start a stream, a second request got 200. Fix: hold the slot until the stream generator finishes (including client disconnect and errors).
B5 Auth only in production: with VAULT_AUTH_TOKEN set in the development profile, unauthenticated requests returned 200. Fix: whenever VAULT_AUTH_TOKEN is set, enforce it on /v1/*, /metrics and the detailed /readyz in every profile.
B6 False 400: has_non_text_parts treats ANY dict key named image_url, input_audio or file as binary content. Repro in production: a tool schema property named "file", or metadata {"file": "report.txt"}, returned 400. Fix: inspect only content parts (messages[*].content[*] with a "type" in image_url, input_image, input_audio, file, input_file). Add false-positive tests.
B7 Errors: invalid JSON from a client returned 503 "Internal masking failure" (OpenAI SDKs retry 5xx automatically); framework errors use {"detail": ...} while 401 uses OpenAI-style errors; no request id is returned. Fix: 400 for client mistakes, 401, 413, 429 with Retry-After, 503 ONLY for fail-closed. One OpenAI-style error body {"error": {"message","type","code"}} everywhere via exception handlers. Return an x-request-id response header on every response and put the same id in the log line. Never echo input in errors.
B8 Injected system message: a "keep [TYPE_N] placeholders" system message is prepended to every request, even when nothing was masked; the upstream saw two system messages. Fix: add it only when the vault is non-empty; if the request starts with a system or developer message, append the instruction to it; otherwise prepend one.
B9 Unscanned numbers and keys: integer values such as {"mobile": 9876543210, "aadhaar_no": 367598341203} and dict KEYS in tool arguments or metadata reached the upstream unmasked. Fix: scan integer leaves (as digit strings; if a detector covers the whole number, replace the value with the token string) and scan dict keys. Document that integers become token strings.
B10 merge_spans can drop a span: input A(0,6) C(4,12) B(10,19) returned only B, so A, which does not overlap B, was left unmasked. Fix: rewrite as greedy selection by priority (rule over SLM, longer, higher score) keeping only non-overlapping spans, losing a span only when a kept span overlaps it. Add property tests (hypothesis): output spans never overlap; every input span is either kept or overlapped by a kept span.
B11 Retention: server.py writes every masked request into the module-level LAST_MASKED_REQUEST in all profiles, even DEMO_MODE=false, including text the detectors missed. Fix: store it only when DEMO_MODE=true; test that production keeps nothing after a request.
B12 Key in logs: the Gemini backend sends the API key in the URL query; the httpx INFO log line and our warning (which prints the exception) both contained the key. Fix: send it in the x-goog-api-key header, set the httpx and httpcore loggers to WARNING, never log exception text containing URLs. Test with a fake key and capture ALL log output at DEBUG level.
B13 Readiness: /readyz returned "ready" and the configured model name while Ollama was unreachable. Fix: /readyz probes the SLM backend and the model (cached at most 10 seconds) and reports ready/degraded/not-ready accurately; show a model name only after a successful probe or call; unauthenticated callers in production still see only the minimal status.
B14 Heuristic fallback: GEMMA_BACKEND defaults to "auto", which falls back to a heuristic with hardcoded demo names (including the author's name). With Ollama down it masked "Aniket Chaudhary" and "Vikram" and missed "Sunita Verma". Fix: delete _heuristic_gemma_fallback and the hardcoded names entirely; the default GEMMA_BACKEND becomes "off" (explicit opt-in; record it in CHANGELOG under Corrections); remove the "auto" mode or make it mean "ollama if reachable at startup, else off, and say so in the startup banner".
B15 SLM layer robustness: /api/tags is called before every SLM call; a new httpx client is built per call; queue timeouts count as backend failures and can open the circuit breaker (overload becomes a 30-second outage); chunks run sequentially; num_predict=512 can truncate JSON; user text is placed unfenced in the prompt. Fix: check the model at startup and cache; one shared client; queue timeouts do NOT trip the breaker (count them separately in metrics); bounded-parallel chunk calls; larger output limit and recovery of partial JSON; fence the text and instruct the model to treat it as data; document that prompt injection can reduce SLM recall while rules still apply.
B16 Startup errors are raw pydantic tracebacks. Fix: catch configuration errors at startup, print a readable list (setting, problem, how to fix) and exit with code 2.
B17 Test fragility: tests/test_metrics.py::test_metrics_import_coverage fails when prometheus_client is installed. Make tests independent of optional extras.
B18 Docs versus code: the README config table lists defaults that the code does not have (UPSTREAM_BASE_URL, GEMMA_MODEL gemma2:2b, NON_TEXT_POLICY "warn", REQUEST_TIMEOUT_SECONDS 30, MAX_CONCURRENT_REQUESTS 100); "pip install vaultproxy" is not published; "PAN check character validation", "91 prefix" and "25+ UPI handles" do not exist in the code; "metadata.id and tool schema names are allowlisted" is false; "zero PII at all log levels" was false (B12); the CHANGELOG says "Guarantee"; Azure and Anthropic compatibility is claimed but untested; scripts/preflight.sh requires Python 3.11 while pyproject says 3.10. Fix: generate the config table from the Settings class, delete unverifiable claims, and add tests/test_docs_vs_code.py that fails when defaults in the README differ from the code.
